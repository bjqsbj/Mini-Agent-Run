# 测试案例与验收

以下是「代码修复与回滚」入口的原有案例。《测试示例.md》第三节要求的 CASE-001 至 CASE-008 在默认「Agent 故障诊断」中运行。[八个单文件故障与验收](Doctor诊断与八例验收.md)

在创建页的「测试清单」选择案例，使用离线演示可重复以下结果。三个快捷现场用于快速体验。完整 JSON 由程序启动时读取；源码、入参、预期和离线候选均可检查。[打开清单](../examples/cases.json)

| 案例 | 现场与复现 | 应如何验证 |
| --- | --- | --- |
| gateway-port · 旧端口 | 配置 5433，服务注册 5432，启动转圈 | gateway 第 49 行连接失败。核对 selectPort(5433,5432) 从 5433 变为 5432；registered 为 null 时保留 configured。基线 1/3，候选 3/3 |
| sync-timeout · 单位错误 | 8 秒被当成 8 毫秒再取最低 2000ms，上游需 7800ms | sync 探针先超时，第 33 行重试耗尽。8 和 2.5 秒分别应为 8000 和 2500ms，默认值与最小值仍为 2000。2/4 → 4/4 |
| export-space · 容量不足 | 8 MiB 可用，归档需要 64 MiB，5,000 行日志中发生 ENOSPC | 跳到第 3,884 行，核对前一行需求和后一行回滚。8/64 返回 false，64/64 返回 true。3/4 → 4/4 |
| vague · 模糊投诉 | 「我觉得Agent不好用」 | 状态为待补充，说明所需现象或触发条件。无工具调用，仅有原始版本。可点击继续排查补充问题 |
| unrelated · 无关请求 | 「请解方程 2x + 5 = 13」 | 状态为已过滤，记录不相关的原因，零工具调用，零修复版本 |
| regression · 错误候选 | 相同导出故障，演示候选误用了严格大于 | 8/64 由错变对，但 64/64 由对变错。前后均为 3/4，任务失败且没有新活动版本。看逐行结果，不只看通过率 |
| healthy · 已修复源码 | 注册端口优先的实现已经存在，模拟环境仍保留故障日志 | 基线 3/3，无需改码，完成任务但只保留原始版本。日志只能提示调查方向 |
| parallel-tools · 工具 ID 串线 | 同轮 call_A、call_B 派发，call_B 先返回。用户以“不好用”开头，同时给出可复现细节 | 反馈通过筛选；agent 第 27 行记录错配。逆序列表应返回 B、A 对应的工具消息，顺序与空列表行为正常。2/3 → 3/3 |

## 自定义输入与人工兜底

- 将「有点难用」这类无法由固定规则精确覆盖的反馈提交给真实模式，查看「LLM 筛选」的理由及最终分类。也可提交「read_state 与 list_jobs 逆序完成后，第二条消息拿到了第一条的 ID」，核对模型能否区分这两种表达。
- 上传自己的模块时，为明确的复现、已知正常输入和边界各写一条独立断言。未提供断言时，真实模型会先拟定，断言及其来源可在基线测评处展开。若预期与业务定义不符，上传独立断言重新验证。
- 在同步探针显示「执行中」时停止，观察后续是否还生成补丁；重新执行后核对新 ID 和旧任务状态。
- 在修复成功后下载原始、修复两个版本，再回滚至原始版本。核对当前文件内容与第一次上传一致，版本列表保留三条。重启后重新打开同一任务复核。
- 搜索导出日志关键词 ENOSPC，只应命中 1 条；清空筛选后恢复 5,000 行。第 4,800 行的 HTML 样本文字应按普通文本显示。

## 自动复验

在项目根目录执行 `npm.cmd test`。验收共 22 项，除清单外还覆盖了 HTTP 上传/回滚/重启、冲突版本写入、模块相对导入、耗时函数中断、断言间隔离、SSE 补读和模型分片协议。测试使用临时数据库，真实模型凭证不参与自动测试。

本次另用真实 DeepSeek 运行 gateway-port，记录到 5 次本地工具调用，以及筛选、基线测评、候选测评和成功修复快照。真实生成的调用次数、补丁文本和先后顺序会随模型决策而变化；线上验收应比对证据与实际断言结果。
